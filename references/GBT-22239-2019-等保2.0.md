# GB/T 22239-2019 信息安全技术 网络安全等级保护基本要求（等保 2.0）

## 基本信息

| 项目 | 内容 |
|------|------|
| 标准号 | GB/T 22239-2019 |
| 俗称 | **等保 2.0** |
| 中文名称 | 信息安全技术 网络安全等级保护基本要求 |
| 替代标准 | GB/T 22239-2008（等保 1.0） |
| 归口单位 | 全国网络安全标准化技术委员会（TC260） |
| 标准类型 | 推荐性国家标准（GB/T） |
| 发布日期 | 2019 年 5 月 10 日 |
| 实施日期 | 2019 年 12 月 1 日 |

## 法律依据

《网络安全法》第二十一条规定国家实行**网络安全等级保护制度**，网络运营者须按等级保护要求履行安全保护义务。等保是法定强制要求，不履行可被处**一万至十万元罚款**，直接负责人处五千至五万元罚款。

---

## 一、等保对象与等级划分

### 等保对象（等保 2.0 全覆盖）

- 基础信息网络（电信网、广电网等）
- 信息系统（含移动互联系统）
- 云计算平台/系统
- 大数据应用/平台/资源
- 物联网
- 工业控制系统

> 除个人及家庭自建网络外，等保 2.0 实现了网络领域全覆盖。

### 五级划分

| 级别 | 受侵害对象与程度 | 典型系统 | 测评要求 |
|------|----------------|---------|----------|
| 一级 | 公民、法人权益轻微损害 | 小型内网、个人站点 | 自主保护，无须测评 |
| **二级** | 公民、法人权益严重损害 | 中小企业官网、一般业务系统 | 定期测评（建议每 2 年） |
| **三级** | 社会秩序/公共利益严重损害 | 金融系统、医疗平台、大型互联网平台 | **每年测评一次** |
| 四级 | 国家安全受损害 | 关键信息基础设施核心系统 | 每半年测评，严格监管 |
| 五级 | 国家安全特别严重损害 | 涉及国家命脉的系统 | 国家专门机构保护 |

## 二、安全要求结构：1+5 模型

```
等级保护对象安全要求
    ├── 安全通用要求（所有对象均须满足）
    │       ├── 技术要求（5 类）
    │       │     ├── 安全物理环境
    │       │     ├── 安全通信网络
    │       │     ├── 安全区域边界
    │       │     ├── 安全计算环境
    │       │     └── 安全管理中心
    │       └── 管理要求（5 类）
    │             ├── 安全管理制度
    │             ├── 安全管理机构
    │             ├── 安全管理人员
    │             ├── 安全建设管理
    │             └── 安全运维管理
    └── 安全扩展要求（按系统类型叠加）

            ├── 物联网安全扩展要求
            ├── 工业控制系统安全扩展要求
            └── 大数据安全扩展要求（附录参考）
```

## 三、安全通用要求——技术要求详解

### 1. 安全物理环境

- 机房选址、防火、防水、防雷、防静电
- 温湿度控制、电力保障（UPS、双路供电）
- 物理访问控制（门禁、监控录像）
- 三级以上须设置专用机房，具备视频监控和电子门禁

### 2. 安全通信网络

- 网络架构安全（分区分域，业务系统与管理系统隔离）
- 通信传输加密（三级以上须使用密码技术保证传输机密性和完整性）
- 网络设备防护（设备鉴别、不必要端口/服务关闭）

### 3. 安全区域边界

- 边界防护：防火墙、入侵检测/防御（三级以上须部署 IPS）
- 访问控制：基于白名单的策略，默认拒绝
- 安全审计：对边界流量和访问行为进行审计
- 恶意代码防范：边界处进行恶意代码检测
- 三级以上须具备异常流量检测能力

### 4. 安全计算环境（核心，控制项最多）

| 控制项 | 二级要求 | 三级要求 |
|--------|---------|---------|
| 身份鉴别 | 口令+账号管理 | **双因素认证**（口令+令牌/证书等） |
| 访问控制 | 基于角色的访问控制 | 须有强制访问控制机制 |
| 安全审计 | 记录用户行为日志 | 审计覆盖所有用户，日志**不可删除** |
| 入侵防范 | 关闭不必要服务 | 漏洞扫描、最小化安装 |
| 数据保密 | 重要数据加密存储 | 传输和存储均须加密 |
| 数据备份 | 本地备份 | 本地+异地备份，须验证可恢复性 |

### 5. 安全管理中心

- 系统管理：统一配置管理和用户管理
- 安全管理：统一安全策略下发
- 审计管理：集中日志收集和分析
- 三级要求：审计管理员、系统管理员、安全管理员须**三权分立**，任一角色不得独立完成全部操作

## 四、安全通用要求——管理要求详解

### 6. 安全管理制度

- 制定覆盖全面的安全制度体系（包括总体安全策略、操作规程等）
- 三级以上须每年对制度进行评审和修订

### 7. 安全管理机构

- 成立安全管理机构，明确岗位职责
- 三级须设置**专职安全管理员**
- 三级以上须定期开展安全检查（至少每季度一次）

### 8. 安全管理人员

- 人员录用背景核查
- 三级以上签署保密协议
- 岗前及在岗安全培训（三级每年至少一次）
- 离岗时立即撤销所有访问权限

### 9. 安全建设管理

- 系统定级、备案
- 三级安全方案须通过专家评审
- 产品采购优先国产密码产品（推荐通过商密认证）
- 软件开发须进行代码审查和安全测试
- 外包服务须签订安全协议

### 10. 安全运维管理

| 管理项 | 三级关键要求 |
|--------|------------|
| 漏洞管理 | 每季度开展漏洞扫描，重大漏洞 48 小时内修复 |
| 日志管理 | 日志留存**不少于 6 个月** |
| 变更管理 | 重大变更须审批，变更后须测试 |
| 应急预案 | 制定预案，每年至少演练一次 |
| 外包运维 | 驻场运维人员须签保密协议，操作须全程审计 |

## 五、安全扩展要求概览

### 云计算安全扩展要求

| 条款 | 要求 |
|------|------|
| 基础设施位置 | 云基础设施须在**中国境内** |
| 虚拟化安全 | 虚拟机间须隔离，防逃逸和越权访问 |
| 镜像和快照保护 | 须加密存储，防止未授权访问 |
| 云服务商选择 | 须签订安全协议，明确双方责任边界 |
| 租户数据保护 | 云服务商不得在无授权情况下访问租户数据 |

### 移动互联安全扩展要求

- 移动终端须通过认证后接入企业网络
- 移动应用上线前须进行安全检测
- 无线接入须加密，禁止私建无线热点

### 物联网安全扩展要求

- 感知节点物理防护（防拆卸/防破坏）
- 感知节点设备须进行身份认证
- 数据采集最小化，传输须加密

### 工业控制系统安全扩展要求

- 工控网络与企业办公网须**物理或逻辑隔离**
- 工控设备须通过工业防火墙防护
- 补丁须经充分测试后安装（不得影响生产连续性）
- 禁止工控系统直连互联网

## 六、等保合规实施流程

```
1. 定级
   ├── 梳理系统清单（每套独立系统分别定级）
   ├── 按 GB/T 22240-2020 评估等级
   └── 专家评审 + 主管部门审批（三级以上必须）

2. 备案
   ├── 向运营地公安机关网安部门提交备案材料
   └── 取得备案证明（含系统编号）

3. 建设整改
   ├── 差距分析（对照本标准逐项自查）
   ├── 制定整改方案（技术 + 管理双线并行）
   └── 实施整改

4. 等级测评
   ├── 委托公安部授权的测评机构
   ├── 测评机构按 GB/T 28448-2019 开展
   └── 出具测评报告（结论：优/良/中/差）

5. 持续监督
   ├── 按周期定期复测（三级每年一次）
   ├── 系统重大变更时须重新测评
   └── 配合公安机关安全检查
```

## 七、三级等保高风险项（测评否决项）

以下任意一项存在，将导致测评结论直接降为"差"，须立即整改：

- 存在**空口令或弱口令**账户（尤其是管理员账户）
- **多人共用**同一管理员账号
- **审计功能未开启**，或审计日志可被管理员删除
- 服务器存在**已知高危漏洞**且未修复
- 重要数据**明文传输**（未加密通道）
- **未建立数据备份**机制，或备份数据无法恢复
- **未制定应急预案**，或从未开展演练

## 八、等保 2.0 与等保 1.0 主要差异

| 变化点 | 等保 1.0（2008） | 等保 2.0（2019） |
|--------|----------------|----------------|
| 保护对象 | 信息系统 | 网络、云、大数据、物联网、工控全覆盖 |
| 技术分类 | 主机/网络/应用/数据安全 | 物理环境/通信网络/区域边界/计算环境/管理中心 |
| 扩展要求 | 无 | 新增云/移动互联/物联网/工控扩展 |
| 二级测评 | 无强制要求 | 要求定期测评 |
| 定级方式 | 自主定级 | 申请批准（须专家评审，三级须主管部门确认） |
| 密码要求 | 未特别强调 | 明确要求使用密码技术（推荐国密算法） |

## 十一、常见问题

**Q：App 需要做等保吗？**
A：需要。App 及其后端服务器均属于等保对象。涉及大量用户个人信息的 App 通常须定为二级或三级。

**Q：云上系统如何做等保？**
A：按"责任共担"原则，云服务商负责物理层和虚拟化层安全，租户负责操作系统及以上各层。须在服务协议中明确划分责任边界，双方分别出具等保合规证明。

**Q：等保二级和三级的核心差别？**
A：三级须双因素认证、三权分立、集中审计且日志不可删、每年测评、专职安全管理员、每季度漏洞扫描，安全要求全面高于二级。

**Q：等保测评结论"差"会有什么后果？**
A：须立即整改并重新测评。情节严重或发生安全事件后被查出的，面临公安机关行政处罚（警告至十万元罚款），高管个人也可能被处罚。
