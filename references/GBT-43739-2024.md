# GB/T 43739-2024 数据安全技术 应用商店的App个人信息处理规范性审核与管理指南

## 基本信息

| 项目 | 内容 |
|------|------|
| 标准号 | GB/T 43739-2024 |
| 中文名称 | 数据安全技术 应用商店的App个人信息处理规范性审核与管理指南 |
| 归口单位 | 全国网络安全标准化技术委员会（TC260） |
| 标准类型 | 推荐性国家标准（GB/T） |
| 发布年份 | 2024 年 |

## 标准简介

本标准为应用商店运营者提供了对入驻 App 开展个人信息处理合规性审核的方法和管理指南，明确了应用商店作为平台方对 App 隐私合规的"守门人"责任。

## 适用对象

- **应用商店运营者**（主要适用方）：华为应用市场、小米应用商店、OPPO 软件商店、苹果 App Store 中国区等
- **App 开发者/运营者**（参考使用）：了解上架审核重点，提前做好合规准备

## 应用商店的平台责任

根据本标准，应用商店应：
1. 对入驻 App 的个人信息处理行为承担**审核责任**（上架前审核）
2. 建立**持续监督机制**（上架后动态管理）
3. 对违规 App 采取**下架、整改等处置措施**

## 上架审核内容

### 一、隐私政策审核

| 审核项 | 要求 |
|--------|------|
| 是否存在 | App 须有独立的隐私政策，不得以用户协议替代 |
| 是否易访问 | 注册/使用前须可访问，不得埋藏 |
| 内容完整性 | 须包含：收集信息类型、目的、保留期限、第三方共享、用户权利等 |
| 语言可读性 | 须使用通俗易懂的语言，避免专业法律术语堆砌 |

### 二、权限申请合规性审核

| 审核项 | 要求 |
|--------|------|
| 权限与功能的关联性 | 申请的系统权限须与 App 核心功能直接相关 |
| 危险权限申请时机 | 须在使用对应功能时实时申请，不得在首次启动时批量申请 |
| 拒绝权限后的降级 | 拒绝非核心权限后，App 应仍可使用基础功能 |

### 三、SDK 管理审核

- App 集成的第三方 SDK 须在隐私政策中列明
- SDK 的数据处理行为须受 App 开发者约束
- 高风险 SDK（如广告 SDK、数据分析 SDK）须重点关注其合规性

### 四、信息收集行为审核

参照 **GB/T 41391-2022**（App 收集个人信息基本要求）：
- 收集范围是否超过必要限度
- 是否存在强制捆绑授权
- 是否存在默认勾选同意

### 五、未成年人保护专项审核

- 面向未成年人的 App 须有专项隐私政策
- 须具备年龄核验机制
- 须取得监护人同意的技术实现

## 动态管理机制

应用商店上架后须持续监督：

| 监督方式 | 说明 |
|----------|------|
| 定期复查 | 对已上架 App 定期重新审核（建议每年一次） |
| 投诉处理 | 建立用户投诉 App 个人信息违规的处理机制 |
| 监管通报联动 | 监管部门通报的违规 App 须及时下架处理 |
| 版本更新审核 | App 大版本更新时，须重新审核个人信息处理合规性 |

## 违规处置措施

| 违规程度 | 处置措施 |
|----------|----------|
| 轻微违规 | 通知开发者限期整改 |
| 较严重违规 | 暂停下载，整改通过后恢复 |
| 严重违规 | 立即下架，情节严重者封禁开发者账号 |

## 对 App 开发者的启示

App 开发者在提交上架前应检查：

- [ ] 是否有独立且内容完整的隐私政策？
- [ ] 所有系统权限申请是否都有对应功能？
- [ ] 是否可以拒绝非核心权限后仍能正常使用？
- [ ] 所有第三方 SDK 是否在隐私政策中披露？
- [ ] 是否存在"未注册视为同意"等无效授权方式？
