# GDPR — 欧盟《通用数据保护条例》（EU 2016/679）

## 基本信息

| 项目 | 内容 |
|------|------|
| 全称 | General Data Protection Regulation（通用数据保护条例） |
| 法规编号 | Regulation (EU) 2016/679 |
| 通过日期 | 2016 年 4 月 14 日（欧洲议会通过） |
| **生效日期** | **2018 年 5 月 25 日** |
| 替代法规 | 欧盟数据保护指令 95/46/EC |
| 监管机构 | 各成员国数据保护机构（DPA），跨境由"牵头监管机构"负责 |
| 法规性质 | EU Regulation，直接适用于所有成员国，无需各国立法转化 |

---

## 一、适用范围：谁必须遵守 GDPR？

### 地域范围（"长臂管辖"）

GDPR 不以企业注册地为限，以下任一情形均须遵守：

| 情形 | 说明 |
|------|------|
| **设立地标准** | 在欧盟境内设有机构，且数据处理与该机构活动相关 |
| **目标市场标准** | 向欧盟境内数据主体提供商品或服务（无论是否收费，未在欧盟设立亦适用） |
| **行为监测标准** | 对欧盟境内数据主体的行为进行监测（如行为追踪、用户画像） |

> **对中国出海企业的影响**：App、电商、SaaS、游戏等只要有欧盟用户，均须遵守 GDPR。未在欧盟设立实体的，通常还须在欧盟指定**书面代表（EU Representative）**。

### 适用的数据类型

- **个人数据（Personal Data）**：任何可直接或间接识别到特定在世自然人的信息
- 包括：姓名、邮箱、IP 地址、Cookie ID、位置数据、设备标识符等
- **匿名化（Anonymisation）**后的数据不适用 GDPR
- **假名化（Pseudonymisation）**数据仍属于个人数据（仍受 GDPR 约束）

## 二、核心角色定义

| 角色 | 定义 | 承担责任 |
|------|------|---------|
| **数据控制者（Controller）** | 决定个人数据处理目的和方式的主体 | 主要合规责任方 |
| **数据处理者（Processor）** | 代表控制者处理数据的主体（如云服务商、SaaS 供应商） | 须签 DPA，对控制者负责 |
| **联合控制者（Joint Controllers）** | 两个或多个主体共同决定处理目的和方式 | 须协议明确各自责任，对数据主体连带负责 |
| **数据主体（Data Subject）** | 个人数据所指向的在世自然人 | 权利持有人 |
| **数据保护官（DPO）** | 负责 GDPR 合规监督的独立角色 | 独立监督，不受处罚 |

## 三、数据处理的六项合法基础（第 6 条）

处理个人数据**必须**满足以下六项之一，否则违法：

| 合法基础 | 说明 | 典型场景 |
|----------|------|---------|
| **同意（Consent）** | 数据主体明确、自由、具体、知情地给予同意 | 营销邮件订阅、非必要 Cookie |
| **合同履行（Contract）** | 为履行与数据主体的合同所必要 | 购物配送需要收货地址 |
| **法律义务（Legal Obligation）** | 为遵守控制者适用的法律义务所必要 | 税务记录保存、AML 合规 |
| **重大利益（Vital Interests）** | 保护数据主体或他人的生命安全所必要 | 紧急医疗情况 |
| **公共任务（Public Task）** | 为公共利益或行使官方权力所必要 | 政府机构、监管机构 |
| **正当利益（Legitimate Interests）** | 控制者或第三方正当利益，且不凌驾于数据主体权益之上 | 欺诈防范、网络安全、内部管理 |

> ⚠️ **正当利益须通过"三步测试"**：①目的合法→②处理必要→③利益平衡（不得凌驾于数据主体利益）。对儿童数据**不得使用**正当利益作为合法基础。

---

## 四、七大数据处理原则（第 5 条）

| 原则 | 核心要求 |
|------|----------|
| **合法、公平、透明** | 处理须有合法基础，方式公平，对数据主体透明 |
| **目的限制** | 数据只能用于收集时声明的特定、明确、合法目的 |
| **数据最小化** | 只收集和处理实现目的所必要的最少数据 |
| **准确性** | 确保数据准确，过时或不准确须及时更正或删除 |
| **存储限制** | 不得超过实现目的所需的时间保留可识别数据 |
| **完整性与保密性（安全性）** | 采取适当技术和组织措施防止未授权处理和数据丢失 |
| **问责制（Accountability）** | 控制者须能够证明遵守上述原则（举证责任在控制者） |

## 五、特殊类别数据（敏感数据，第 9 条）

以下类型数据原则上**禁止处理**，仅在满足特定例外条件时方可处理：

| 类别 | 说明 |
|------|------|
| 种族或民族出身 | |
| 政治观点 | |
| 宗教或哲学信仰 | |
| 工会成员身份 | |
| 遗传数据 | |
| 生物特征识别数据 | 仅用于唯一识别自然人时属特殊类别 |
| 健康数据 | 包括医疗记录、残疾信息等 |
| 性生活或性取向数据 | |

**可处理的例外情形（须严格满足）：** 数据主体明确同意、劳动法义务、医疗目的、公共卫生、科学研究等。

## 六、数据主体的八项权利（第 12-22 条）

| 权利 | 核心内容 | 响应时限 |
|------|----------|---------|
| **知情权** | 收集数据时须以清晰易懂的语言告知控制者信息、目的、保留期限、第三方共享等 | 收集时立即告知 |
| **访问权（第 15 条）** | 确认数据是否被处理，并获取免费数据副本 | **1 个月内**（可延至 3 个月） |
| **更正权（第 16 条）** | 要求更正不准确或补充不完整的数据 | 1 个月内 |
| **删除权/被遗忘权（第 17 条）** | 特定情形下要求删除全部数据（如目的已实现、撤回同意等） | 1 个月内 |
| **限制处理权（第 18 条）** | 特定情形下要求暂停处理但不删除（如数据准确性存争议期间） | 立即标记限制 |
| **数据可携权（第 20 条）** | 以通用机器可读格式获取数据，并可转移至其他控制者 | 1 个月内 |
| **反对权（第 21 条）** | 随时反对基于正当利益/公共任务的处理，以及直接营销处理 | 营销须立即停止 |
| **免于自动化决策权（第 22 条）** | 不受仅基于自动化处理（含画像）的、具有重大法律影响的决定约束，须提供人工审查渠道 | 须提供申诉渠道 |

## 七、控制者的主要合规义务

### 7.1 记录处理活动（ROPA，第 30 条）

须维护书面的数据处理活动记录，内容包括：
- 控制者名称和联系方式
- 处理目的
- 数据主体类别和个人数据类别
- 接收数据的第三方（含跨境接收方）
- 跨境传输机制
- 预期删除时限
- 安全措施概述

> 250 人以上组织须强制维护，小组织如涉高风险处理活动也须维护。

### 7.2 隐私设计与默认（第 25 条）

- **Privacy by Design**：在系统/产品设计阶段就内嵌数据保护原则
- **Privacy by Default**：默认采用最高隐私保护设置，无需用户手动调整

### 7.3 数据处理协议（DPA，第 28 条）

与每家处理者（包括云服务商、SaaS 供应商、数据分析服务商等）须签订书面 DPA，内容须包括：
- 处理的主题、时限、性质和目的
- 个人数据类别
- 控制者的指示和处理者的义务
- 保密义务、安全措施、协助义务
- 分处理者的使用条件
- 合同终止后的删除/归还义务

### 7.4 数据泄露通报（第 33-34 条）

| 通报对象 | 时限 | 触发条件 |
|----------|------|---------|
| **监管机构（DPA）** | **72 小时内** | 发生个人数据泄露，除非不可能对自然人权利造成风险 |
| **数据主体** | **无不当延迟** | 泄露可能对数据主体权利和自由造成**高风险** |

**通报内容须包括：** 泄露性质、数据类型和数量、DPO 或联系人信息、可能后果、已采取或拟采取的补救措施。

## 八、数据保护官（DPO，第 37-39 条）

### 须强制任命 DPO 的情形

- 公共机构或公共部门（军队除外）
- 以**大规模、系统性监控**数据主体为核心活动
- 以**大规模处理特殊类别数据**或刑事定罪数据为核心活动

### DPO 独立性要求

- 不得因履行 GDPR 职责而受处罚或解雇
- 直接向最高管理层汇报（如董事会）
- 可为内部员工或外部顾问（须签合同）
- 须向所在成员国 DPA 登记 DPO 联系信息
- 数据主体可直接联系 DPO 行使权利

---

## 九、数据保护影响评估（DPIA，第 35 条）

### 须强制开展 DPIA 的情形

- 对数据主体进行**大规模系统性自动化评估**（含用户画像）
- **大规模处理特殊类别数据**（健康、生物识别等）
- **大规模系统性监控公共场所**（如人脸识别摄像头网络）
- 新技术部署（EDPB 或各国 DPA 可发布必须评估的具体类型列表）

### DPIA 须包含内容

1. 处理活动的系统性描述及目的
2. 必要性和相称性评估
3. 对数据主体权益造成的风险评估
4. 拟采取的缓解措施及残余风险
5. 与 DPO 的协商意见（如已任命）

> 若 DPIA 显示高风险且无法缓解，须在处理前向 DPA **事先咨询（Prior Consultation）**。

## 十、数据跨境传输（第五章，第 44-50 条）

将个人数据传输至欧盟/EEA 以外须满足以下机制之一：

| 机制 | 说明 | 是否适用中国 |
|------|------|------------|
| **充分性决定** | 欧委会认定目标国具充分保护水平（英、日、韩、以色列等） | ❌ 中国暂无 |
| **标准合同条款（SCC）** | 使用欧委会 2021 年发布的标准合同条款 | ✅ 最常用 |
| **约束性企业规则（BCR）** | 跨国集团内部统一保护规则，须 DPA 批准 | ✅ 可用，审批周期长 |
| **认证机制** | 经批准的认证方案 | 尚无广泛适用方案 |
| **行为准则** | 经批准的行业行为准则 | 少数行业有 |

> **中国企业注意**：使用 SCC 时，还须进行**传输影响评估（TIA）**，评估目的地国家（中国）的法律是否会削弱 SCC 的保护效果，并据此落实补充措施。

## 十一、有效同意的要件

| 要件 | 说明 | 常见违规 |
|------|------|---------|
| **自由给予** | 拒绝同意不得影响服务获取 | 不同意就不让用 |
| **具体明确** | 每个处理目的须单独同意 | 打包同意多个目的 |
| **充分知情** | 告知须清晰易懂，不得使用晦涩法律用语 | 隐私政策晦涩难懂 |
| **明确无歧义** | 须通过积极的 opt-in 行为表示 | 预先勾选默认同意 |
| **可随时撤回** | 撤回须与给予同样便捷 | 撤回需多步操作 |

## 十二、Cookie 合规要点

| Cookie 类型 | 是否需要同意 |
|------------|------------|
| 严格必要 Cookie（登录状态、购物车、安全） | **不需要** |
| 功能性/偏好 Cookie（语言、主题设置） | 通常需要 |
| 分析/统计 Cookie（Google Analytics 等） | **需要**（除非完全匿名化） |
| 广告/营销追踪 Cookie | **必须 opt-in 同意** |

**Cookie Banner 常见违规：**
- 拒绝按钮比接受按钮更难找或更小 → 违规
- 预先勾选"接受所有" → 违规
- 无法一键拒绝所有非必要 Cookie → 违规
- 继续浏览视为同意 → 违规

## 十三、罚款与执法（第 83 条）

| 档位 | 最高罚款 | 典型违规行为 |
|------|----------|------------|
| **第一档** | **1000 万欧元**或全球年营业额 **2%**（取高者） | 处理者义务、DPO 义务、认证机构义务、儿童同意 |
| **第二档** | **2000 万欧元**或全球年营业额 **4%**（取高者） | 基本处理原则、合法基础、数据主体权利、跨境传输规则 |

**典型处罚案例（参考）：**

| 案例 | 金额 | 违规原因 |
|------|------|---------|
| Meta（爱尔兰 DPC，2023） | 12 亿欧元 | 将欧盟用户数据跨境传输至美国违规 |
| Amazon（卢森堡，2021） | 7.46 亿欧元 | Cookie 同意及广告定向违规 |
| Instagram/Meta（爱尔兰，2022） | 4.05 亿欧元 | 儿童个人数据公开展示违规 |
| Google（法国 CNIL，2022） | 1.5 亿欧元 | Cookie 拒绝机制设计违规 |

## 十四、与中国个人信息保护法（PIPL）的对比

| 维度 | GDPR（EU） | 中国 PIPL |
|------|-----------|---------|
| 生效时间 | 2018 年 5 月 | 2021 年 11 月 |
| 适用范围 | 处理欧盟在世自然人数据 | 处理中国境内自然人数据（含境外） |
| 合法基础数量 | 6 项 | 同意 + 5 项法定情形 |
| 敏感数据范围 | 8 类特殊类别 | 敏感个人信息（含金融、行踪等，略有差异） |
| 数据主体权利 | 8 项 | 7 项（基本对应，无可携权细则） |
| 数据跨境机制 | 充分性/SCC/BCR | 安全评估/标准合同/认证（三选一） |
| DPO 类角色 | DPO（特定情形强制任命） | 个人信息保护负责人（大型平台强制） |
| 最高罚款 | 全球营业额 4% 或 2000 万欧元 | 年营业额 5% 或 5000 万元人民币 |
| 儿童年龄门槛 | 16 岁（成员国可降至 13 岁） | 14 岁 |
| 问责制举证 | 控制者举证（Accountability） | 个人信息处理者举证 |

## 十五、GDPR 合规实施路线图

```
第一步：数据摸底
  ├── 梳理所有个人数据处理活动
  ├── 建立/更新数据处理活动记录（ROPA）
  └── 绘制数据流图（含第三方共享和跨境流转）

第二步：合规差距分析
  ├── 评估每项处理活动的合法基础
  ├── 审查现有隐私政策、Cookie 政策
  └── 核查第三方合同是否含 DPA 条款

第三步：整改落地
  ├── 更新隐私政策（简洁、全面、分层展示）
  ├── 部署合规的 Cookie 同意管理平台（CMP）
  ├── 建立数据主体权利请求处理流程（1 个月内响应）
  ├── 完善数据泄露通报预案（72 小时内可启动）
  └── 与所有处理者补签 GDPR DPA

第四步：高风险场景专项
  ├── 开展 DPIA（用户画像、生物识别等高风险场景）
  ├── 评估跨境传输合规性（SCC + TIA）
  └── 确认是否须任命 DPO 及 EU Representative

第五步：持续运营
  ├── 定期审查 ROPA（重大业务变更时更新）
  ├── 数据安全事件应急演练（确保 72 小时可报告）
  └── 跟踪 EDPB 最新指南及执法动态
```
